I kept the optimizer, gradient clipping, maximum sequence length, and random seed consistent across SFT and both DPO runs. For the two DPO experiments, I started from the same SFT checkpoint and used it as the frozen reference model. I then selected the checkpoint with the highest validation reward accuracy for each run. For HH-RLHF, this was step 400 out of 468, while for UltraFeedback, it was the final training step. The final SFT checkpoint, at step 937, also had the lowest validation loss, so I used it in the subsequent experiments.

The LoRA experiment followed a different configuration. Instead of using the same setup as the other DPO runs, I trained a LoRA adapter on SmolLM2 with TRL's \texttt{DPOTrainer}. I used a higher learning rate and a smaller batch size, and I added a negative log-likelihood (NLL) term to the loss to encourage the model to generate the chosen answer. I explain the motivation for this additional term in the next section.

\paragraph{Generation.}
I used greedy decoding for every evaluation by setting \texttt{do\_sample=False}. Since the models did not sample from the output distribution, temperature and top-p settings did not affect generation. I allowed each model to generate up to 512 new tokens and used a repetition penalty of 1.0, a length penalty of 1.0, and no n-gram blocking. Within each comparison, I kept the generation settings identical for SFT and DPO so that differences in the judge's evaluations would reflect the models' outputs rather than differences in decoding strategies. I used the plain prompt template described in Section~\ref{sec:data} for the Qwen runs and the model's chat template for the SmolLM2 runs. The only exception to these settings is the decoding sensitivity check in the results section, where I repeated two comparisons with a repetition penalty of 1.1 for both models.
